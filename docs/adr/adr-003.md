# ADR-003: Using SQLite over MySQL or Postgres

**Date:** 2026-10-11
**Status:** accepted

## Context

My fitness tracker web app only has 1 user in mind for now, and there won't be that much data involved. Additionally, the course only lets me use one data store for my system. SQLite is easier to setup for me, my peer and professor, as it involves the use of a file to store the database, so no server configuration or setup is required.

## Decision

I am going to use SQLite to store my data and adatabase tables, and it will live in the data tier. The service and domain tiers will not care about this, as all the data models will only be concerned with the data tier.

## Consequences

No configuration is needed to run a server, as the database file automatically gets created for the user on their first run, making easier for the application to run. Switching from SQLite to either MySQL or Postgres only requires a change in the data tier. If I ever decide to host the site and continue using SQLite, then I will need to make sure the hosting site allows the database file to persist over time. I may need to revisit this decision at that point.
