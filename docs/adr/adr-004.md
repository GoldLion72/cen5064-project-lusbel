# ADR-004: JWT in an httpOnly Cookie for Authentication

**Date:** 2026-11-21
**Status:** proposed

## Context

The WholeFit web application nneds to support the ability for users to create an account. This way each user can sign up and start creating workouts that only they can see. The server needed a way to determine who was logged in and making each request. I could have either stored the sessions on the database or used JSON Web Tokens as browser cookies in httpOnly.

## Decision

I decided to go with the JWT httOnly cookie approach. Every time a user registers or logs in, the backend sends a JWT as a cookie that expires in 1 day. 

## Consequences

The server does not need to keep track of the sessions by storing them in the SQLite database. User sessions expire in 1 day, and logging out clears the cookie. If a user were to exit the site without logging out, they would not be required to login again. A potential problem could be that the tokens cannot be revoked before the expiration date. If this becomes a major problem, than either a switch would need to be made to store sessions on the database, or I would need to find a way to blacklist certain tokens in the backend.
